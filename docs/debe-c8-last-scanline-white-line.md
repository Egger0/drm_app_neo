# C8 叠层帧末最后扫描线白线（BOE 顶部 / HSD 底部）

> 对应修复：`src/overlay/overlay.c`、`src/overlay/opinfo.c`。
> 这是 DEBE 硬件在 C8（palette/索引）层参与 alpha 混合时的一个边界行为，
> 应用侧通过调整叠层几何规避，不涉及内核改动。

## 现象

打开干员信息卡（arknights overlay 上屏）时，屏幕边缘出现一条 1px、横贯
全屏的白色细线：

- BOE 倒装屏：白线在屏幕**顶部**；
- HSD 正装屏：白线在屏幕**底部**；
- 不开卡片（主界面）无白线；
- 与素材、视频内容、fade 颜色无关：把卡片 fade 颜色改成红色，白线仍为白色。

## 根因

两种屏的白线其实是**同一条**：整帧画面的**最后一条显示扫描线**
（显示行 639）。BOE 屏倒装，内核用 DEBE 负 stride 倒扫做上下翻转
（见 `boe-flip-180.md`），最后一条扫描线被翻到物理顶部；HSD 正装则在
物理底部。

DEBE 在 **C8 层参与 alpha 混合**时，帧末最后一条扫描线的边界处理存在
缺陷，会把它输出成白线：

- 主界面时叠层虽然也挂载在 (0,0) 全屏，但全局 alpha=0（全透明），不参与
  混合，无白线；
- 打开卡片后叠层不透明、per-pixel alpha（调色板项自带 alpha）生效，
  最后一条扫描线即吐白；
- 寄存器对比（卡片开/关两次 devmem dump）确认：两种状态唯一实质差异就是
  叠层的 alpha 配置，其余（层几何、行宽、缓冲地址、TCON 时序、背景色）
  完全一致。

排查中已排除：

- 叠层缓冲最后一行内容（dump 非全宽白，仅左下角素材自带 54px 白条）；
- UI 缓冲、视频层（开卡前后同一个 loop 视频）；
- 调色板内容（内核影子表正确、fade 实际渲染为黑）；
- DRM 层几何（`modetest -p` 全对）；
- DEBE 背景色寄存器（0x804 本来就是 0）、MODCTL 控制位。

## 修复

让 C8 叠层**不覆盖最后一条显示扫描线**，从而不参与该行的 alpha 混合：

1. `src/overlay/overlay.c`：叠层挂载高度由 `OVERLAY_HEIGHT`（640）改为
   `OVERLAY_HEIGHT - 1`（639）。缓冲仍是 360x640，只让 DEBE 少扫一行，
   不越界。
2. `src/overlay/opinfo.c`：停靠位置按机型选择：
   - 倒装机（BOE，存在 `srgn,scanout-yflip` DT key）：CRTC_Y=1，配合
     内核 `y' = vdisplay - y - h` 映射后覆盖显示行 0..638；
   - 正装机（HSD）：CRTC_Y=0。

两种机型最终都让显示行 639 只剩视频层、无 C8 混合，白线消失。

副作用：叠层内容第 639 行（fade 三角底边、左下竖条底端）不再显示，
视觉上只有 1px 差异，基本无感。

## 验证

- BOE 实机：打开干员信息卡，顶部白线消失（修复前必现，修复后无）；
- app 反汇编确认修复代码已编译进二进制（`drm_warpper_mount_layer_rect`
  调用、`access(SDROT_YFLIP_DT_PATH)` 选择停靠 Y）；
- HSD 逻辑对称（`settle_y=0`），未实机验证，待正装机确认。
